# Running this screen against a real PLC over EtherNet/IP

This project ships as a **self-contained trainer** — the NetLogic simulates the
gas train, mod motor and switches. To drive it from a real Logix controller
(ControlLogix / CompactLogix / Micro850) you add an **RA EtherNet/IP** driver
and bind the `Model` tags to controller tags.

Everything below is what you need on both sides. The driver node itself is
created by Studio's wizard (see step 2) — it is not hand-authored in this repo,
because Studio owns that node's module version and rewrites the project's
dependency list when the driver is added.

---

## 1. Decide which mode you want

| Mode | What the PLC does | What the HMI does | Use when |
|---|---|---|---|
| **A — Mirror (keep the trainer)** | Receives the simulated values | Keeps simulating, writes state out to the PLC | You want the trainer intact but visible to a PLC / SCADA / a real 7800 test panel |
| **B — Full real I/O** | Runs the whole burner sequence | Displays PLC values and sends operator commands only | You are wiring this to an actual gas train |

Mode A needs no logic changes — just bind the tags (step 3) and the values flow
out. **Mode B** additionally requires deleting the simulation from
`ProjectFiles/NetSolution/ValveProvingLogic.cs` — see step 5.

---

## 2. Add the driver in Optix Studio (2 minutes)

1. In the project tree, right-click **CommDrivers ▸ New ▸ RA EtherNet/IP Driver**.
   Studio adds the `FTOptix.RAEtherNetIP` module dependency for you.
2. Right-click the new driver ▸ **RA EtherNet/IP Station**.
3. Select the station and set:
   - **Route** — the connection path to the controller, in the form
     `IP\Backplane\Slot`, e.g. `192.168.1.10\Backplane\0`
     (slot `0` for CompactLogix, the CPU slot number for ControlLogix).
   - **Timeout** — leave the default unless the network is slow.
4. Open the station's **TagImporter**:
   - **Offline** — Browse to your Studio 5000 `.ACD`/`.L5X` and import.
   - **Online** — flip the Online/Offline toggle and enter the controller route.
5. The imported tags land under
   `CommDrivers/RAEtherNet_IPDriver1/RAEtherNet_IPStation1/Tags/…`

Default node names are `RAEtherNet_IPDriver1` and `RAEtherNet_IPStation1`; if
you rename them, use your names in the paths in step 3.

## 3. Bind the Model tags to the controller tags

For each row in the table below, select the `Model` variable in Optix, and in
the property panel set its value source to the matching driver tag
(drag the driver tag onto the Model variable's **Value** field — Studio writes
a DynamicLink). The screen and NetLogic keep using `Model/...`, so **nothing in
the UI or the C# has to change**.

### Controller ➜ HMI (field status; make these PLC-written)

| Model tag | Optix type | Logix type | Meaning |
|---|---|---|---|
| `VP1` | Boolean | BOOL | SSOV V1 (SKP15) open |
| `VP2` | Boolean | BOOL | SSOV V2 (SKP25) open |
| `VPS` | Boolean | BOOL | Valve proving switch — TRUE = test failed |
| `Pilot` | Boolean | BOOL | Pilot valve energized |
| `Lockout` | Boolean | BOOL | Safety lockout active |
| `Interlock` | Boolean | BOOL | Safety interlock string closed |
| `RunningInterlock` | Boolean | BOOL | Running interlock closed |
| `RunIntlkFault` | Boolean | BOOL | Running-interlock fault active |
| `LGP` | Boolean | BOOL | Low gas pressure switch made |
| `HGP` | Boolean | BOOL | High gas pressure switch tripped |
| `LowFireSwitch` | Boolean | BOOL | Low fire end switch made |
| `HighFireSwitch` | Boolean | BOOL | High fire end switch made |
| `SupplyPressure` | Float | REAL | Inlet gas pressure, in. H2O |
| `ChamberPressure` | Float | REAL | Test-volume pressure, in. H2O |
| `DownstreamPressure` | Float | REAL | Pressure after V2, in. H2O |
| `ModMotorR` | Float | REAL | Mod motor feedback wiper, ohms (0–135) |
| `ModMotorW` | Float | REAL | R–W leg, ohms |
| `ModMotorB` | Float | REAL | R–B leg, ohms |
| `FiringRatePercent` | Float | REAL | Actual firing rate, 0–100 % |
| `FlameSignal` | Float | REAL | Flame amplifier signal, VDC |
| `State` | Int32 | DINT | Sequence state (see enum below) |

### HMI ➜ Controller (operator commands and settings)

| Model tag | Optix type | Logix type | Meaning |
|---|---|---|---|
| `RateSetpoint` | Float | REAL | Firing-rate pot, 0–100 % |
| `LGPSetpoint` | Float | REAL | LGP trip point, in. H2O |
| `HGPSetpoint` | Float | REAL | HGP trip point, in. H2O |
| `VPSSetpoint` | Float | REAL | VPS allowed differential, in. H2O |
| `AutoMode` | Boolean | BOOL | AUTO (1) / MANUAL (0) |

`StateText` (String) is generated by the HMI from `State` — leave it local, do
not bind it.

### `State` enum (must match the PLC)

```
0  Standby          4  TestV1        8  Ignition
1  PurgeHoldHigh    5  Fill          9  Run
2  Purge            6  TestV2       10  Lockout
3  Evacuate         7  PurgeHoldLow
```

## 4. Create the tags in Studio 5000

Controller-scoped tags, names matching the tables above exactly:

```
// BOOL
VP1, VP2, VPS, Pilot, Lockout, Interlock, RunningInterlock,
RunIntlkFault, LGP, HGP, LowFireSwitch, HighFireSwitch, AutoMode

// REAL
SupplyPressure, ChamberPressure, DownstreamPressure,
ModMotorR, ModMotorW, ModMotorB, FiringRatePercent, FlameSignal,
RateSetpoint, LGPSetpoint, HGPSetpoint, VPSSetpoint

// DINT
State
```

A UDT wrapping them (e.g. `Burner`) also works — the driver imports the members
and you bind `Model/VP1` to `Burner.VP1`, etc.

## 5. Mode B only — remove the simulation

In `ProjectFiles/NetSolution/ValveProvingLogic.cs`, delete these and let the
bound PLC tags supply the values instead:

| Delete | Because |
|---|---|
| `SimulatePressure()` + its call in `Tick()` | `ChamberPressure` now comes from a transmitter |
| `SimulateActuator()` + its call in `Tick()` | `ModMotorR/W/B` and the end switches come from the field |
| `UpdateFlameSignal()` + its call in `Tick()` | `FlameSignal` comes from the flame amplifier |
| `UpdateGasPressureSwitches()` | `LGP` / `HGP` become real switch inputs |
| `RunSequence()` + its call in `Tick()` | The PLC owns the sequence; the HMI just reads `State` |

Keep `UpdateGraphics()` (all the animation) and `ApplyRatePot()` /
`RatePotChanged()` (the operator's rate command). The banner/faceplate text
switch already keys off `step` — in Mode B drive it from the `State` tag.

**Safety note:** the burner sequence, lockouts and all interlock supervision
must live in the safety controller / burner control, not in this HMI. Treat the
screen as an operator interface only.

## Runtime license tokens

FactoryTalk Optix Runtime licenses are **token containers** — you pick a bundle
and spend tokens on the features you enable. Published bundle sizes:

| Size | XS | S | M | L | XL |
|---|---|---|---|---|---|
| Tokens | 5 | 8 | 11 | 15 | 21 |

Token consumers are: controller connections, concurrent web clients, alarms,
recipes, PDF reports, data logging, database connectivity, OPC UA and MQTT.
The largest consumers are usually multiple web clients, OPC UA, and databases.

**What this project actually uses** (counted from the project files):

| Feature | This project |
|---|---|
| Controller connections | **1** (the EtherNet/IP station above) |
| Tags | **27** |
| Native/local client | 1 (the panel screen itself) |
| Web clients | `WebPresentationEngine` is enabled on port 8666 — set `MaxNumberOfConnections` to the number you actually need, or delete the engine if you never use a browser client |
| Alarms | **none configured** (`Alarms.yaml` is empty) |
| Data logging / DataStores | **none configured** |
| Recipes | **none configured** |
| Reports | **none configured** |
| OPC UA server/client | **none configured** |
| MQTT | **none** |
| Database | **none** |

So this is a small, single-controller, no-options application — the low end of
the range. **Rockwell does not publish the per-feature token costs**; they come
from the *Runtime Entitlement Sizing Guide* and the **Runtime Sizing Tool** on
the FactoryTalk Optix landing page, which outputs the exact bundle and catalog
number. Run those numbers through it rather than trusting an estimate.

Two things that will move the number if you are watching cost: each additional
**concurrent web client** and any **OPC UA / database** connection you add.
Leaving `WebPresentationEngine` enabled with a high connection count is the
easiest way to overspend on an application this small.
