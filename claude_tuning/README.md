# claude_tuning — PID Tuning Advisor for FactoryTalk Optix

A FactoryTalk Optix port of the [pid-tuning-trainer](../pid-tuning-trainer/)
web tool: enter the current PID gains for a 90° actuated valve loop, pick the
symptom you're seeing in the field, and get a targeted gain adjustment with
reasoning and field notes — then verify it against a built-in FOPDT loop
simulator that models real 90° valve nonlinearity before touching the live loop.

## What's in this folder

| Path | Contents |
|---|---|
| `NetSolution/TuningAdvisorLogic.cs` | Recommendation engine NetLogic — 12 symptoms, weighted by loop type, actuator speed, and valve characteristic. Exports `Analyze()`, `LoadRecommendation()`, `UpdateStandardForm()`, `UpdateHealthSummary()`. |
| `NetSolution/ValveLoopSimulator.cs` | Loop simulator NetLogic — FOPDT process + parallel PID with derivative-on-PV and back-calculation anti-windup, through linear / equal-% / quick-open / butterfly valve curves. Exports `StartSim()`, `PauseSim()`, `ResetSim()`, `Disturb()`. |
| `Model/ModelVariables.md` | Exact variable names, types, and defaults to add to each NetLogic in Studio. |
| `UI/ScreenLayout.md` | Screen build guide: widget tree, bindings, DataLogger/Trend setup, styling. |

## Why the .optix project file isn't checked in

Optix project containers are generated by FT Optix Studio with
machine-specific GUIDs and can't be reliably hand-authored. Everything
portable — the C# logic, the variable model, and the UI recipe — is here;
Studio assembles it in a few minutes:

## Setup (FT Optix Studio)

1. **New project** → name it `claude_tuning`, any Windows or Ubuntu target
   with NetLogic support.
2. **Add the NetLogics**: Project view → Logic → right-click → New → Runtime
   NetLogic, twice. Name them `TuningAdvisorLogic` and `ValveLoopSimulator`.
   Open each in the code editor and paste the corresponding `.cs` file over
   the generated stub (keep the class name identical to the file's).
3. **Add the variables** from `Model/ModelVariables.md` as children of each
   NetLogic (names must match exactly). Link the simulator's `Kp`/`Ki`/`Kd`/
   `ValveCharacteristic` to the advisor's via dynamic links so
   `LoadRecommendation()` retunes the running sim.
4. **Build the screen** per `UI/ScreenLayout.md` — entry widgets on the left,
   recommendation panel and Trend on the right, buttons wired to the exported
   methods via Method-invocation events.
5. **DataLogger + Trend** for the live chart (instructions in the UI guide).
6. Run. Enter gains → pick a symptom → **Analyze** → **Load → Sim** → watch
   the response, use **Disturb** to test load rejection, compare `IAE`
   between tunes.

## Symptom catalog

Too Slow / Sluggish · Overshooting · Oscillating/Hunting · Steady-State Offset ·
Need More Aggressive · Slow to Open · Slow to Close · Noisy/Jittery Output ·
Integral Windup · Derivative Kick · Low-Fire Instability · Poor Load Rejection

Each recommendation scales its adjustment by loop type (fuel/air/FGR loops get
gentler moves than flow; temperature gentler still), actuator stroke speed, and
valve characteristic, and includes controller-specific notes (Logix PIDE,
Siemens LMV5) plus safety warnings where relevant (e.g. slow-closing fuel
valves are flagged as a burner safety issue, not a tuning problem).

## Notes on form

Gains are **parallel form** (Kp, Ki, Kd independent). The advisor also
publishes `TiSeconds` (= Kp/Ki) and `TdSeconds` (= Kd/Kp) so values can be read
straight into standard/ISA-form controllers, which is what most field
controllers (PIDE in gain-independent mode, LMV Pb/Tn) actually take.
